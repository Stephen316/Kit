# Component Architecture Rules

These rules are MANDATORY for any work on Next.js or React applications in this workspace (e.g. `AgentUI/` and any other Next.js app). They are non-negotiable and rank alongside the formatting, React Doctor, and no-stubs gates. Violating them means the work is not done.

## Scope

Applies to any change touching React source: `.tsx`, `.jsx`, and `.ts`/`.js` files that contain React components, hooks, or JSX, in any Next.js or React project in this workspace.

## Rule 1: Dedicated Component Files — NEVER Inline Components

Every React component MUST live in its own dedicated file. There are NO exceptions.

### FORBIDDEN

- Defining a component inside another component's body (nested function/arrow components that are re-created on every render).
- Declaring multiple unrelated components in a single file as a shortcut instead of giving each its own file.
- Defining a component inline at its usage site (e.g. an IIFE returning JSX, or an arrow component assigned to a variable solely to render it once locally).
- Passing inline-defined component functions as props (e.g. `render={() => <Thing />}` where `<Thing />` is a freshly declared component, not a small render callback).
- Anonymous components attached directly to JSX, routing tables, or config objects.

### REQUIRED

- One component per file, named to match the file. The file's primary export is that component.
- Co-locate a component's own small, private subcomponents only when they are genuinely part of the same unit AND are still declared at module scope (never inside another component's render). When in doubt, split into separate files.
- Components are always declared at module top level, never inside another function/component body.
- Reusable components live under the project's components directory; route-specific components live with their route but still in their own files.

The only constructs allowed inline are: JSX elements (markup), and short render callbacks/event handlers that do NOT declare a new component (e.g. `items.map((i) => <Row key={i.id} item={i} />)` is fine because `Row` is imported, not declared here).

## Rule 2: NEVER Edit Third-Party Components Without Explicit Approval

You MUST NOT modify any third-party / vendored component code without the user's explicit, case-by-case approval.

### What counts as third-party

- Anything under `node_modules/`.
- Generated or vendored library code, including ShadCN-generated primitives under the project's UI directory (e.g. `components/ui/*`), Radix wrappers, and any file whose header or origin marks it as generated by an external CLI/registry.
- Any file the React Doctor / formatting steering already flags as "not our code" (the ShadCN boundary rule in `ReactDoctor.md` applies here too).

### The rule

- Do NOT edit, refactor, reformat, "fix", or restyle third-party components.
- If a third-party component needs different behavior or styling, wrap it in your own dedicated component file and compose/extend it there, or pass props/className — never patch the vendored source.
- If the only correct fix genuinely requires changing third-party source, STOP and ask the user for explicit approval first. State exactly which file and what change, and wait for a clear yes before proceeding. Do not assume approval.
- This rule overrides convenience: never "just tweak" a generated component to save a step.

## Verification

Before considering React work complete, confirm:

1. Every component you added or touched lives in its own dedicated file at module scope — zero inline or nested component definitions.
2. No third-party / generated component source was modified without explicit user approval recorded in the conversation.

If either check fails, the work is not done. Fix it before reporting completion.
