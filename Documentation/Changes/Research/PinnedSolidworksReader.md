# Pinned SOLIDWORKS reader integration and planning alignment

## Behavior

A04 adds a research command around the existing SOLIDWORKS reader.
It verifies one pinned Git asset, preserves the SDK neutral JSON and writes a separate field-path evidence receipt.
Native-only content, diagnostics, native codes and unqualified direction/frame mappings remain explicit.
Typed reconstruction does not establish independent semantic or native acceptance.

The [plan](../../Reference/Research/AutomationPlan.md) incorporates the newer parallel-session design and early-reader prerequisites.
The [register](../../Reference/Research/AutomationSteps.md) is the only maintained step-status record.
It identifies A04 qualification work, A08 supervisor/application boundaries, optional A10 runners and A14 process gates.
A models-off pilot does not depend on optional model runners.
Proposed local tests and model-run command exceptions remain unauthorized.

Root and scoped `AGENTS.md` instructions require PR comments at change/stage start, meaningful progress, completion, blockers and handoff.
Accepted pushes and failed verification also require comments.
All A01–A16 implementation stays on PR #94.

## Usage and limits

Follow [the reader guide](../../Reference/Research/SolidworksResearchReader.md).
Use a pinned SLDPRT path and an unused output directory.
No model or CAD installation is required.
Assemblies, embedded Kit documents and unqualified portable-conversion claims are outside this command's scope.
Unknown semantics remain research work rather than inferred successful decoding.
See [the retained-evidence gotcha](../../Gotchas/Research/ReaderReplayIsNotPortableSemantics.md).
