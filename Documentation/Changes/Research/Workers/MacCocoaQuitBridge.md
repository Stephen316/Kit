# Request normal quit from an existing Cocoa application

`re/automation/ApplicationWorkers/MacCocoaQuit.py` supplies an in-process research bridge. It checks the native macOS main thread, reads the existing `NSApp` from the loaded system AppKit framework, and sends `terminate:` using the method's fixed Objective-C signature. An unsupported platform, missing runtime symbols, missing application instance or wrong thread causes an explicit refusal. [Existing application instance](https://developer.apple.com/documentation/appkit/nsapplication/shared), [Normal termination](https://developer.apple.com/documentation/appkit/nsapplication/terminate%28_%3A%29), [Apple Silicon calling conventions](https://developer.apple.com/documentation/Apple-Silicon/addressing-architectural-differences-in-your-macos-code)

The disposable AppKit fixture reads the exact source from Git, checks it against the checkout, and stages it with its SHA-256. Embedded CPython verifies that pin before executing the module. The fixture checks refusal before creation of `NSApp` and from a worker thread after startup. It arms the existing Darwin process observer before requesting quit. The delegate acceptance, cancellation, lost reply and duplicate cases distinguish the bridge call from the observed process result. [AppKit fixture](AppKitQuitDelegateWitness.md)

The bridge requires a trusted in-process caller to authorize the operation, confirm that the application is idle and empty, and hold the required custody. The bridge call returns control only when AppKit permits it. A return alone leaves the exit outcome unknown. The Fusion quit path remains operator-driven. The exact armed authorization and a licensed signed-in Fusion witness remain prerequisites for unattended use. Hosted verification of this embedded bridge is pending.
