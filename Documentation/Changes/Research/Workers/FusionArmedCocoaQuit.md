# Request a guarded Fusion quit on macOS

The owner can opt into a normal in-process Cocoa quit for a dedicated licensed macOS Fusion research installation. Use Python 3.10 or later in the observer and embedded add-in so the processes share the same monotonic clock. Pin the reviewed checkout revision, reload the matching add-in, and set `"macos_automatic_quit": true` in the trusted installation JSON. Add `--request-quit` to the [exact exit observer](FusionQuitObserver.md) command for the accepted Phase A attempt. Without that flag, the observer prompts the operator to quit in Fusion. [Python monotonic clock](https://docs.python.org/3.14/library/time.html#time.monotonic)

The observer verifies the accepted A03 attempt and the old process, keeps the dispatch lock, and arms the Darwin watch before publishing a request. It records one request per accepted restart intent. The request binds the armed intent digest, retained fence, exact watcher and target, pinned callback and bridge sources, and a deadline bounded by both the watch and the consumed readiness grant. A request-specific lease lasts through the observation. The add-in checks both leases without waiting. It verifies the same installed bytes, accepted owner intent, empty queue and exact peer before reserving one action. It then checks expiry, custody, startup, active jobs and open documents again on Fusion's main thread before calling the [Cocoa bridge](MacCocoaQuitBridge.md). [Fusion application properties and main-thread events](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/core_Application.htm)

The observer accepts a Darwin exit without a callback return record when a durable reservation exists. The receipt preserves the unverified cause. A callback return can follow cancellation or another AppKit outcome. A return or expiry without an exact exit leaves the handoff parked. A missing or refused reservation cannot produce a qualified automatic exit receipt. The same restart intent cannot publish another automatic request.

The automatic request holds the restart fence across a missing old PID. To release it, the [owner replacement command](FusionReplacementLaunch.md) needs an exact exit receipt and must observe the exact new process from its authorized launch request. The new add-in checks those records and its live identity before clearing the fence. When the prior process is still live after a timeout or refusal, a new operator-directed watch can observe a manual quit. If that observation succeeds, use its receipt for the same authorized replacement procedure. [Automatic quit fence](../../../Gotchas/Research/Workers/FusionAutomaticQuitFence.md)

The hosted disposable process cases exercise the pinned callback, Darwin watch, one-use reservation and replacement gate. The fixture simulates the Fusion application state and callback outcome. The separate disposable AppKit fixture exercises the Cocoa bridge and delegate. Both sets passed in the 154-case macOS suite at PR head `3cd136ad` and tested merge `e1fa7f1d`.
