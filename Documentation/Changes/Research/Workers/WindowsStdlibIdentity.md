# Windows process identity without site packages

The research worker's Windows process identity helper uses `ctypes` for `OpenProcess`, `WaitForSingleObject`, `GetProcessTimes` and `CloseHandle`. It retains the `windows:<FILETIME>` identity with both halves of the native 64-bit creation value. It uses a non-inheritable handle with query-limited and synchronize rights, returning no live identity for an absent or exited process. Other access and wait failures raise an error. IDs larger than a native DWORD are refused before conversion. [OpenProcess](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-openprocess), [WaitForSingleObject](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-waitforsingleobject), [GetProcessTimes](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getprocesstimes)

The Windows research job includes a process case that runs the helper in `python -I -S`, checks its own identity against its current process handle, checks a live disposable peer, and verifies refusal of a wrapped PID and disappearance after peer exit. At PR head `47de6ad0`, the hosted Windows research job passed all 91 cases, including this process boundary. [Hosted Windows job](https://github.com/TryUniCAD/Kit/actions/runs/43772995626/job/132992935662)

Windows Fusion Phase A still needs a pinned route to load the helper into the add-in, protected Windows record and lock access, and owner-private endpoint admission. The record path needs equivalent ancestor and file handle protections, including exact handle `ChangeTime`, regular files, one link and exclusion of reparse points. Future Windows owner admission needs to verify the Windows user SID and desktop session from the peer token and use the exact FILETIME for the process generation. The supervisor continues to own controller leases, accepted outputs and process containment.
