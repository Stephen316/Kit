# Fresh SOLIDWORKS P03 package metadata

`BuildFreshMetadata` builds typed metadata for the generation-19000 research fixture with one Front Plane rectangle and blind boss. Pass the projected `BossWriterInput`, its `OrdinaryConfig` and `ResolvedSystem`, and an explicit `MetadataContext`. The result supplies the existing package header, configuration-manager, Definition, core and empty property, OLE and open-time inputs. The caller keeps custody of output path, calendar, sidecar indices and other package members. [Research constructor](../../../../../../re/solidworks/WriterResearch/FreshPartMetadata.py)

The header uses the configuration's document update and body stamps and the projected world bounds. Its self reference uses the profile's own file identity with the self-reference flag. CMgr uses that identity with the ordinary external flag, and shares the same visual state with Config-0. The caller supplies the next allocated tree ID and the three independent seconds roles for creation, update and modification. The summary creation time remains separately expressible. [ModelHeader](../../../../../../re/solidworks/WriterResearch/ModelHeader.md) · [CMgr file record](../../../../../../re/solidworks/WriterResearch/CmgrTail.md)

The revision rows take their system names from the generated system and scene owners and their authored names from the generated sketch and extrusion. The inherited history uses a caller-selected earlier graph clock for the document log and IDs 1 through 16. The remaining default nodes use the current creation time. The Front and Origin references use that same inherited graph clock. The two authored rows receive their own creation and rebuild times. This narrow schedule follows the fresh P03 history shape. It leaves the next tree ID with the caller's allocator because multiple native nodes consume IDs without creating log rows. [Revision log layout and evidence](../../../../../../re/solidworks/WriterResearch/ModelHeader.md#revision-log-construction)

Definition repeats the caller's primary rotation in its preamble and stores one greater than the allocated appearance ID. The caller supplies the camera, three view records, journal attachment and terminal double. Their selection and the surrounding native window profile still need fresh-file verification. The header also requires the actual caller-owned package code, separate license type and terminal state. The supported codec currently accepts the measured package-code and license-type pair. Geometry and Kit's own license supply neither value. [Definition appearance allocator](../../../../../../re/solidworks/WriterResearch/DefinitionJournal.md#appearance-id-counter) · [Native save classification](SolidWorksEModelLicense.md)
