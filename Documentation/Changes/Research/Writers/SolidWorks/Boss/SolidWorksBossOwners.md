# SOLIDWORKS ordinary boss configuration and system owners

`BuildBossOwners` combines a projected boss with explicit document preferences and clocks. `OrdinaryConfig` receives the same transfer atom as the resolved feature and uses the projected world bounds for its model and fresh mass cache. The annotation group selects `*Front` or `*Right` from the sketch's datum and adds `*Top` for the solid. The rebuilt model's cosmetic entry uses the same document update stamp as `ModelStamps`. Its geometry and body stamps are separate inputs. [Existing configuration writer](../../../../../../re/solidworks/WriterResearch/OrdinaryConfig.py)

The resolved system constructor assigns the known folders, cabinet nodes and principal tree identities. All three datum views derive from the same world bounds. Origin retains its own Front attachment when the authored sketch is on Right. Filetime words, the last update state for each system member, reference timestamps and Origin's profile state remain explicit. The profile must refer to the same datum and Origin timestamps. The existing `BeginResolvedPart` obtains both the part and environment references from the generated configuration's allocation map. [Resolved system writer](../../../../../../re/solidworks/WriterResearch/OrdinaryResolved.py)

The caller still supplies the visual `color.p2m` profile, its installation path and appearance ID, the physical density, environment and lights, hatch and plane preferences, current formatter values, sketch-block UUID and model partition marker. Unsupported visual or provider branches remain gated by their codecs.
