# P04 SolidWorks sketch geometry research reader

Run `python re/solidworks/archive/SketchEvidence.py` from the repository root with Git and the repository Python environment available. The command writes a JSON report for all eleven P04 discovery captures. Each row includes the capture and configuration stream hashes, native sketch object index, geometry interval, points in metres, line endpoint indices, native length parameter identities, ordered point operands, and logical relation targets. It checks every decoded length against the corresponding independently reopened feature measurement.

The reader verifies the fixed capture revision, the receipt digest, the measurement digest, and all eleven native file digests before interpreting their data. It reads the MO 19000 configuration archive with the existing tag, string and layout engine and uses the witnessed native map initialization. The display segment between the two geometry groups uses an exact-build research layout from the native pointer trace, with typed pointer checks, list counts and bounded relative payload widths. A configuration with a different version, a missing reference, an unexpected tag type or an unsupported count fails the read.

The command reaches both sketch returns and the enclosing relation manager return in every capture. All 66 decoded lengths and 88 line-axis relations match the independently reopened measurements. The baseline A and YZ boundaries match the licensed traces. The display layout preserves the map at both returns, and the [configuration map replay](../../../../re/solidworks/records/P04SketchResidence.md#offline-map-replay) continues through the following presentation fields. [Geometry and native pointer evidence](../../../../re/solidworks/records/P04SketchGeometry.md), [licensed relation manager trace](../../../../re/solidworks/records/P04SketchGap.md#follow-the-second-sketch-return)

The distance handles resolve to local geometry slots and native point IDs. All 66 ordered operand pairs match the saved reopened sketch relations, including the two cut offset dimensions that share operands. The decoded points reproduce each saved length by Euclidean distance or the indicated horizontal or vertical component. The YZ capture exchanges the two offset dimension classes while retaining their operand IDs and scalar values.

The member dword read after the visual record matches all 110 point relation incidence counts in the independent reopen. Removing the verified distance operands leaves one incidence on the rectangular profile's first corner and one on its separate origin point in each capture. Those are the two endpoints of the native type-9 coincidence. The cut profile has no residual point incidences. The report gives the residual counts and preserves the unresolved archive representation of the coincidence itself.
