# Independent Fusion analytic geometry serialization

## Behavior and usage

The internal `convert.formats.Fusion.GeometryCodec` modules construct a solid cylinder from semantic dimensions without reading a source file, invoking a CAD runtime, or copying topology payloads.
`CylinderBody(Radius, Height, BasePoint)` uses millimetres and a positive-Z axis.
`GeometryStamp(Product, Version, SavedAt)` supplies explicit printable provenance.
`EmitCylinderSmt(Model, Stamp)` returns an SMT text stream.
`EmitCylinderSmb(Model, Stamp)` returns a typed binary SMB stream, with explicit conversion of dimensional fields to centimetres and units metadata 10.
Plane direction vectors remain dimensionless while radius vectors and positions scale by their declared field roles.

The writer derives all 26 records.
The records are the header, body, lump, shell, three faces, four loops and four coedges.
The other records are two edges, three surfaces, two vertices, two circles, and two points.
It rejects nonfinite, nonpositive, overflowing, or numerically collapsed dimensions.
The emitted body has no borrowed attributes, native source identifiers, or feature history.

The existing bounded ASM initial-table reader additionally accepts the observed no-history flags-2 profile and requires EOF after its explicit `End-of-ASM-data` marker.
Its existing history path still returns only the initial table; this change does not add general journal evaluation.

## Evidence and limitations

Fusion 2706.1.17 accepted the production SMT output for radius 15 mm, height 11 mm, and base `(20, -30, 5)` mm.
It measured one solid, three faces, two edges, two vertices, volume `7.7754418176350715` cm³, and the expected center and bounds.
Fusion retained all measurements after native save and reopen.
See [production acceptance](../../../re/Fusion/LocalOracle/Brep/ProductionAcceptance.json) and [generation provenance](../../../re/Fusion/LocalOracle/Brep/kit_production_cylinder.json).

The production binary serializer also passed the native binary import route, insertion into a direct design, save, and reopen, ending with zero open documents.
Its [acceptance record](../../../re/Fusion/LocalOracle/Brep/ProductionBinaryAcceptance.json) includes the temporary-body center discrepancy and the correct persistent measurements; [generation provenance](../../../re/Fusion/LocalOracle/Brep/kit_production_cylinder.binary.json) binds the generated bytes to semantic inputs.
See [binary import behavior](../../Gotchas/Conversion/Fusion/FusionBinaryGeometryImport.md) and [account-specific export restrictions](../../Gotchas/Conversion/Fusion/FusionGeometryExportRestrictions.md).

The [persistence guide](../../Reference/Research/FusionDataModel.md) links the detailed topology and journal data model.
Complete-file compatibility cases send independently generated binary solids through the existing ASM token and geometry readers.
The cases check three dimension sets, topology reciprocity, and rejection of trailing data.
General automated compatibility tests run only in PR CI; local checks were static or explicitly authorized native application acceptance.
This is an internal analytic geometry capability, not a complete F3D/F3Z writer or a general BRep converter.
Full parametric document generation, persistent topology naming, arbitrary surfaces, and history editing remain incomplete, and production adapter discovery stays disabled.
