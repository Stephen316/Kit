# Typed Fusion Protein packages

## Behavior and usage

`MaterialCodec.Package.ReadPackage` reads the complete qualified `.protein` ZIP into an immutable `MaterialPackage`. `EmitPackage` regenerates the complete ZIP from that model. `MakePackage(PackageId, AssetId, Timestamp, Schemas, Assets)` creates a package from fresh caller-supplied identities, a timezone-qualified timestamp, schema declarations and typed material assets. No CAD runtime, source archive, raw XML member, saved record or padding is an authoring input.

The model retains four typed package/core metadata records, schema and stream resource links, checked `SchemaNode` declarations and the existing typed `MaterialAsset` values. `SchemaModels` derives the binary property vocabulary from these declarations, so XML and binary properties cannot silently use unrelated schemas. Defaults, bounds, choices, labels and inheritance remain explicit schema metadata. Unknown declaration tags, attributes, child relationships or text are rejected.

The writer derives connection XML, resource XML, package metadata, content-type declarations, the package-format declaration, stream-version text, schema XML and all three material binary streams. It allocates new property blocks and writes an ordinary stored ZIP through the production archive writer. The reader supports the qualified native compressed package as well. ZIP compression, XML formatting, attribute order and unused block padding are not retained opaque data.

The full package is bounded to 16 MiB, including declared expansion. The package also has at most 64 schemas, 1 MiB per XML member, 20,000 schema nodes and nesting depth 8. The reader rejects undeclared resources, extra ZIP members, duplicate schema links, mismatched schema UIDs, unsupported stream versions, document types and processing instructions. Existing binary store validation remains active.

`DocumentModel.Materials` contains `MaterialPart(Name, Package)` values. `ReadDocument` and `EmitParsed` handle these explicitly alongside typed BRep histories. The document boundary validates the material manager's part name, physical/appearance reference vectors, body-to-manager references, asset roles, definition identities and library identities. Nonempty dangling references fail; legacy empty assignments remain representable. Unknown document part types still fail instead of being retained or discarded.

The [independent authoring entry](FusionAuthoredMaterials.md) describes the public material specification and body joins. The [binary codec](FusionMaterialCodec.md) and [research grammar](../../../../re/Fusion/Reconstruction/ProteinInstances/MaterialGrammar.md) describe scalar/property encoding.

## Verification

The production writer was exercised in independent complete documents with fresh material identities and schema-derived values. Fusion 2706.1.17 accepted both solids with valid material identity, 1000 kg/m³ density, correct mass and center of mass, and healthy feature history. Both solids also passed rollback, rebuild, driving-height edits, save and reopen.

The [cylinder report](../../../../re/Fusion/LocalOracle/Authored/ProductionMaterialDocumentAcceptance.json) records one solid with 3 faces, 2 edges and 2 vertices. Its initial 17.25 mm height has 8.467573949129104 cm³ volume, approximately 0.008467573949129 kg mass and center `(0,0,0.8625)` cm. Editing height to 23 mm produces 11.290098598838801 cm³ and 0.011290098598838802 kg, with center approximately `(0,0,1.15)` cm. Both sketch and extrusion remain healthy.

The [rectangle/cuboid report](../../../../re/Fusion/LocalOracle/RectangleAuthoring/NativeAcceptance.json) separately records the independently authored 17×23×31 mm cuboid. Its one body has 6 faces, 12 edges and 8 vertices, 12.121 cm³ volume and 0.012121 kg mass. Editing height to 37 mm produces 14.467 cm³ and 0.014467 kg. Initial and edited centers are `(0.85,1.15,1.55)` cm and `(0.85,1.15,1.85)` cm. The report also includes a separate native extrusion from the authored sketch with native default density; that case does not define the independent package's density.

Remote compatibility cases cross complete `.protein` and `.f3d` file boundaries. They cover the six-instance, eleven-schema native package, complete semantic package re-emission, density/color edits and unknown members. The cases also cover schema/resource mismatches, forbidden XML declarations, unsupported stream versions, missing document packages and incompatible asset roles. Local Black, steering compliance, Ruff, mypy and strict Pyright checks passed. No local tests or production code execution ran in this implementation task. The [typed document re-emission report](../../../../re/Fusion/LocalOracle/RectangleAuthoring/TypedReemission.json) records complete decoding and regeneration of three segments, 228 physical entity records, one history and a nine-schema/four-asset package. Its unchanged re-emission is byte-identical across all 108,583 bytes. A subsequent semantic edit changes the two typed density fields from 1000 to 2870 kg/m³. [Native acceptance of the edited material](../../../../re/Fusion/LocalOracle/RectangleAuthoring/EditedMaterialNativeAcceptance.json) verifies mass 0.03478727 kg initially and 0.04152029 kg after the height edit to 37 mm. The acceptance also verifies correct density, centers, geometry, timeline health, rollback, rebuild and save/reopen. The edited input SHA-256 starts `ba5659ad`; the native saved result starts `49514fd3`.

## Qualified limits

This is the observed single-asset-folder package profile with embed option 49 and AssetTableOfContents 3.1, property stores 3.2, AssetLibVersion 1.0. External textures, arbitrary resources, additional package folder kinds, unknown XML declarations and legacy library variants are rejected. Supporting `.protein` does not establish support for every other auxiliary member in a native `.f3d` document. Full arbitrary native document conversion remains bounded by the other qualified part codecs.
