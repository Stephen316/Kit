# Saved Fusion point coincidence

The public Fusion partial reader projects a point-to-point `coincident` relation when its two saved lists name the same distinct sketch points in either order. Read the archive with `open_document(path, strict=False)`. The projected relation follows the saved argument order, and its attributes retain both native lists. The record still requires its exact constraint class and code, zero dependency slots, ownership by the sketch definition, and typed point backlinks to that sketch. Other constraint kinds keep their existing operand-order checks. [Public Fusion adapter](FusionPublicAdapter.md)

Inspection of the pinned archives found this layout in all six P01, eight P03 and eleven P04 boss rectangle sketches. The constraint names the corner point `228` and separate origin anchor `205`. Both points resolve to the measured sketch origin, and their native identities remain distinct. The historical API measurements corroborate the relation type and sketch origin. The operand identities and ordering come from the saved records.
