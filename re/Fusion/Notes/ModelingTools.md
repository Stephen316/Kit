### Saved study findings

Study scripts, reports and capture paths in this section are relative to [the Study directory](../Study/README.md).

Non-distance holes can retain an inactive saved depth. It is reported as cached data, never as the active extent. Hole diameters are stored model parameters. Thread definitions are recovered for the captured families described below; complete helical geometry regeneration remains unfinished. The six hole reference files compare these settings, position and direction directly with Fusion's API.

`hole-placement-decoding.json` compares five more hole definitions, including reversed distance/through-all, one/three sketch points and a circular-edge center. Every stored position is checked against API or actual input coordinates. Placement mode, direction and diameter are compared with the completed feature. Sketch-point association records/tags and center descriptors are preserved, without claiming the full associative definition. The axis proxy's stored origin can use a different context from the final hole position and is retained separately; general assembly coordinate contexts remain unverified.

`edge-tool-decoding.json` compares 15 fillet/chamfer examples, including multiple sets, curvature continuity and a changed tangency weight. Each edge set resolves its own parameter bindings and selection owner. This initial stage covered endpoint variable-fillet radii and left asymmetric flip unresolved; the later variable-fillet and asymmetric-flip stages below extend those observed cases. Chamfer definition records preserve their independent modes and observed flip flags. None of this reconstructs the selected B-rep edges.

`split-decoding.json` compares five planar split cases: extension on/off, origin and offset construction planes, and one/two target bodies. The tool proxy's stored operation flag agrees with the feature, and both input proxy owners are checked. Counted target descriptors remain explicit without claiming decoded body topology or regenerated result solids. Selection proxies with optional numeric attributes use the same bounded list reader as ordinary proxies.

`thread-decoding.json` compares seven cases from `threadmodes-d51d2ae60564` and `threadmodes-9574579d310b`. Straight metric family/size/designation/class, pitch, three diameters, degree-valued angle, internal/external, cosmetic/modeled, handedness and full/partial length controls match the API. High/low location codes and numeric length/offset bindings are explicit. Full-length files retain inactive native length/offset values even when the API getters return null; these values are never treated as active thread extents. Modeled-thread table pairs remain opaque and are not treated as ASM indices. The initial capture errors are retained in `threadmodes-6b6a0a9b4a69`. The first requested-left creation remained right-handed in the API and native file; the one-case holdout uses the documented feature edit position and establishes actual left-handed evidence. Cylindrical selection owners are checked, but persistent face mapping, tapered/other-family layouts and helical geometry regeneration remain unsupported.

`tapped-hole-decoding.json` adds three files in `tappedholes-409e96788503`: default cosmetic, explicit partial cosmetic and default modeled tapped-hole inputs. The native hole and attached thread refer to each other explicitly; the child has no independent timeline index and uses `ThreadDepth` rather than the standalone `ThreadLength` role. Native tap type, stored hole-diameter parameter, position, attached-thread flags and active extents match the API. The default inputs produced children whose API full-length flag is false with a 1 cm thread depth, so the decoder preserves that actual result rather than inferring a mode from fixture filenames. General parent/child extent coupling remains partial. The stored hole-diameter parameter is not assumed to be the thread nominal diameter, and an empty native child name is not replaced by an invented runtime name.

These files also establish that the short thread selection proxy still has one primary face descriptor; its secondary counted reference list is empty. The shared reader now validates both zero- and one-entry secondary lists, without assigning their semantic role. The previously observed fixed proxy length implicitly assumed one secondary entry. Focused regressions cover plain distance/through/to holes, standalone thread extents/handedness, multiple face descriptors and attributed stitch proxies. For un-attributed hole headers, the field previously skipped as a zero attribute count is now correctly parsed as a tap-type code; the plain-hole outputs remain compatible.

`emboss-decoding.json` compares six files in `embossmodes-e40cc931d978`: raised/engraved, shifted, rotated, chain-disabled and two-profile embosses. Explicit numeric binding roles agree with API depth/offsets/rotation, and owned selections recover profile membership and the target's native historical body ID/name. One native descriptor can reference multiple separately terminated profile sets; the shared `resolve_sketch_profiles` helper preserves those groups instead of flattening them into one contour. A prior Sweep profile comparison and four malformed-control/count/owner checks support the bounded readers. Face recipes and body anchors resolve ownership without assigning exact ASM face identities. Two numeric header values remain opaque. Only planar targets were captured; wrapped geometry, text, general trimming and regeneration remain unverified.

`draft-decoding.json` compares eight files in `draftmodes-9b1a30f74aed`: signed single angle, direction flip, tangent chain, symmetry, two angles, planar-face pull reference and multiple faces. Explicit angle bindings, active/inactive angle handling and owned face groups match API controls/counts/body names. Seven construction pull-plane references match independently decoded geometry; the planar-face pull reference preserves its recipe and body identity without claiming exact plane geometry. Three malformed cases and the earlier cylindrical Draft fixture are checked. The fixed-plane header combination and two finite stored doubles are retained without inventing general field or coordinate meanings. Parting-line modes, exact face mapping and drafted geometry regeneration remain unsupported.

`emboss-text-decoding.json` adds four completed exports in `embosstext-cd769aa41cdf`: editable Text Emboss, Text Deboss, mixed Text/circle-profile and two-Text inputs. A typed descriptor and leaf explicitly name the native Text object in its owning sketch; glyph geometry never chooses that identity. Consumed sources preserve optional opaque `txt_tag_base`, exact observed layout bytes and numbered Height/Text binding slots, with reciprocal parameter/owner checks. All 145 API comparisons and eight malformed guards pass; thirteen prior rectangle outputs, six path outputs and six ordinary Emboss controls remain exact. All four complete main-reader Text arrays and Emboss settings match the report. Font rendering, glyph generation, wrapped surfaces, context transforms and exact target topology remain unresolved.

`special-fillet-decoding.json` adds nine successful exports: automatic/explicit FullRound, all-edge Rule topology variants, asymmetric Rule offsets, BetweenFaces and two swapped-role holdouts. Typed owned proxies/aggregate descriptors establish the source lists and historical body anchors; reciprocal parameter bindings recover radius or offsets. FullRound stores sideOne/sideTwo/center in that order. Rule BetweenFaces stores sourceTwo before sourceOne, confirmed by exact recipe exchanges in the swapped holdout. Native topology codes3/2/1 map to API Both/Rounds/Fillets0/1/2; a second selector repeats the API topology code. Context lists and point caches remain separate evidence, never persistent face identities. Main output exposes `special_fillets`, attaches successful settings and clears only their former tool failures. Ordinary fillet/chamfer outputs remain with their existing reader; multi-set/source combinations, exact topology, fillet geometry and regeneration remain unresolved.

`hole-point-source-decoding.json` resolves four selected points in the original single/multiple SketchPoint Hole captures. Owned providers and separate naming records independently encode the same sketch ID and entity tag; reciprocal support links and native point ownership agree. The multi-point association list has native order middle, first, last, while the position providers are first, middle, last. A tuple join preserves that correspondence, including after the raw association pairs are swapped. Stored association tags remain distinct opaque fields. Parent-component sketch placement and three separately framed coordinate copies corroborate each selected point. One actual saved feature.position getter and four original requested input positions supply explicitly distinguished evidence. Six malformed/ambiguous guards and three unrelated Point/AtCenter controls pass.

Main output exposes `hole_point_sources` and adds successful `point_sources` to Hole settings. Supporting faces, center-edge source identities, point-context matrix/tail semantics, arbitrary placement variants and assembly contexts remain unresolved. `decode_hole_point_sources.py` reproduces this focused report; it does not clear unrelated Hole or selection failures.

`hole-support-decoding.json` decodes owned support and extent provenance in fourteen saved Hole captures: ten bounded-face sources, two explicit origin-plane sources and two source sketches. An AtCenter edge input is separate from its face-position provider. One ToEntity extent explicitly names a target face recipe; two ThroughAll extents contain native body inputs, retained without inventing a user-selected target. The direct dependency table and separate core-context route must agree with owned position/direction/extent references. Existing detailed sketch-point sources stay with their earlier reader. Ninety-nine bounded comparisons and six malformed guards pass. Original support-entity getters were not captured, so no API support-identity getter comparison is claimed. Exact face/edge geometry, context transforms, persistent topology and unobserved support variants remain unsupported.

Main output exposes `hole_supports` and adds successful support, position-support, center-edge, native-body and core provenance to Hole settings. ToEntity target provenance and ThroughAll body inputs enrich the existing extent object; numeric settings and point associations retain their earlier readers. Only supported provenance status is updated, without treating a recipe as an evaluated face or edge.

`cylinder-thread-resize-decoding.json` independently checks nine thread archives across cosmetic, modeled, partial, handedness and internal variants. Every formerly rejected differing-radius surface now agrees with the captured ThreadInfo major diameter divided by two for external threads, or minor diameter divided by two for the internal thread. The eight external caches have physical radius 0.591675 cm; the internal cache has radius 0.513675 cm. Their stored parameter scales remain 0.6. Forty owned boundary endpoint occurrences corroborate these radii, and each main-reader geometry matches. Direct cylinder-surface getters were not captured. Prior wire regression controls retain all fifteen graph topologies/geometries: thirteen graph outputs stay exact, and two compare through the documented analytic field correction.

`variable-fillet-decoding.json` adds three intermediate-radius definitions and an endpoint-only control. Counted position bindings and the separate StartRadius/EndRadius/MidRadius list share their common fillet flags, selection-owner checks, set index, tangency weight and trailer with the existing reader. Twenty parameter role/name/value comparisons agree with actual getters. The two-point getter/native arrays are radii `[.24,.18]` and fractions `[.75,.25]`, reversing the setter request; stored order is preserved. Four exact payload replays, eight malformed guards and three old default controls pass. Main output adds `variable_fillets` and recovered feature `tool_settings`, resolving only the corresponding old unsupported-set-layout warning. Selected ASM edge identity/orientation, general interpolation and fillet geometry remain unresolved.

`asymmetric-fillet-flip-decoding.json` adds three actual unequal-offset fillets: the same offsets with opposite `isFlipped` values, plus swapped offsets with the original flag. The same-offset definitions differ only at byte5; the swapped case changes parameter values while retaining identical definition references. The shared edge-set parser opts into this boolean through a narrow callback, preserving default behavior, common flags, selection ownership, set order and trailer checks. Nine parameter comparisons, three exact payload replays, six malformed guards and three legacy default controls pass. Input continuity1 and requested rolling-ballTrue normalize to actual continuity2 and rolling-ballFalse; decoded values follow actual getters. Main `asymmetric_fillet_flips` publishes the flag and resolves only the corresponding unsupported set-layout failure. Exact selected ASM edge orientation and absolute offset-side mapping remain unresolved.

`boss-api-availability.json` preserves three actual public Boss creation attempts. All fail at `BossFeatures.add` with `Design Extension is not available`; all owned documents close successfully, and no native archives are produced. Exact executed sources and failure journals remain available. These attempts add no Boss decoding coverage, native class or successful fixture.

`parting-line-draft-decoding.json` adds three actual fixed/moving parting-line Draft exports. Common angle bindings and owned selection parsing are shared with the fixed-plane reader. Separate native layouts establish fixed versus moving type, two input faces, one parting edge, and two fixed edges in the moving case. The typed recipes share an explicit historical body anchor; an independently decoded native XY plane supplies the pull reference. Both fixed angle contrasts and the moving single-angle getter match. Moving direction and chaining remain null because their native discriminators have not been independently contrasted. All eight previous fixed-plane settings, two legacy malformed errors and nine new guards pass. Main `parting_line_drafts` clears only each successful Draft's former class/header error; the setup SplitFace layout warning remains explicit.

`draft-no-merge-attribute-decoding.json` resolves six Draft EDGE diagnostics through the mirrored orientation of an existing two-sibling chain: the EDGE points to a no-merge head, which points to a terminal generic naming attribute. Six new payloads replay exactly; 168 previous naming dictionaries, ten existing tail chains and eight malformed guards pass across the focused saved blobs. Two distinct edges carry the same recovered name/index/components in each new blob. Both candidates remain available, and the shared name does not select an edge or establish merge behavior.

`thread-body-route-decoding.json` independently qualifies six historical native BODY source routes across the three plural Thread captures.
