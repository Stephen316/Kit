### Saved study findings

Study scripts, reports and capture paths in this section are relative to [the Study directory](../Study/README.md).

`asm-decoding.json` checks six `.smb`/`.smbh` body/history streams from three existing files. The token reader reaches the final marker and exact EOF, preserves contiguous record boundaries, and finds all non-null pointer indices within each record table. This validates token framing, not the identity of the final visible solid. A blob can contain several intermediate bodies. History header values are retained separately and must not be assumed to use the same coordinate context as final geometry.

`brep-decoding.json` adds typed topology links, reciprocal ownership, closed coedge rings and vertex positions. API evidence from `breptruth-2dfc22bbf5eb` comes from new local imports of three study-owned files. Stored graph candidates match the counts and vertex coordinates of all six resulting API bodies (a hole, a filleted body and four split pieces). These are diagnostic candidate matches, not proof of persistent native body identity. Topology traversal uses the initial geometry entity table; journal and trailing-state records remain separate tokens. Body transforms and raw header unit fields are retained without applying a guessed conversion.

`body-binding-decoding.json` follows a typed design mapping table to an exact history-blob filename and explicit native body objects. Its opaque handles must not be used as ASM record indices: the observed single-body fillet stores handle `2`, while its matching leading ASM body is record `1`. When the declared leading roots fit the mapping count, the reader provides an **experimental ordered-root candidate** for each entry. Candidate geometry matches all six API bodies in the focused evidence, but broader ordering/component/history variants remain unverified. Stored tags such as `0_275` are internal tags, not recovered user-visible body names. These tables appear under each design stream's `body_blob_bindings`.

`body-property-decoding.json` checks four interleaved root/component bodies in `namedbodies-3c7c11fc2924`, including a Unicode name. Repeated collection lists and reciprocal references establish component ownership; a unique owner/typed-helper field anchor locates the bounded UTF-16 custom name without assuming a fixed material-string length. Empty stored names remain null instead of inventing runtime labels such as `Body1`. The ordered root candidates match each body's topology and component-local vertices in this additional assembly, but remain experimental. Properties are under `body_properties` and are attached to matching blob entries only when the collection owner agrees.

The named-body sample also exposed history markers without ordinary record terminators. `Begin-of-ASM-History-Data` and `End-of-ASM-History-Section` are now standalone markers rather than being merged into the next entity. The framing and B-rep evidence snapshots were refreshed: 12 blobs reach exact EOF, and journal pointer semantics are not claimed. Version-8 browser/ACT index framing was checked on this file and an earlier file; their field schemas remain undecoded.

`body-placement-decoding.json` compares eight body placements against API vertex/proxy coordinates: four named root/component bodies plus translated, rotated, uniformly scaled and nonuniformly scaled bodies. The latter files already contain transformed vertices with identity body transforms, so feature matrices are not applied to their caches again. For supported root candidates with explicit owners and absent/recognized-identity body transforms, `body_placement` composes the decoded occurrence matrices. This uses the observed Fusion centimetre convention without interpreting the history header's scale field. Non-identity body transforms remain uninterpreted and prevent world-coordinate output. Root association is still experimental, and vertices alone do not describe curved extrema or complete trimmed surfaces.

`body-selection-decoding.json` records an initial 225-archive snapshot: 395 body anchors, 111 descriptors and 106 selection proxies resolve through explicit typed references, including the two original bodies in the multiple-input path pattern. Four named-body comparisons and four malformed-reference checks support the joins. Historical input identities remain separate from resulting/current bodies and ASM indices. Two component-context proxies remain explicitly unresolved in this snapshot. Current output is under `body_selections`.

`brep-recipe-decoding.json` checks structural framing for 26 native body/face/bounded-face recipes in five trim, tapped-hole and Boundary Fill files. Each grouped term retains its ASCII name, stored index and tagged numeric reference; numeric matches to stream objects are explicit without assigning persistent topology meanings. Focused reassembly reproduces all 26 record bodies exactly, and four malformed count/tag cases are rejected. Header values and payload words remain uninterpreted. This check establishes record framing, not a native archive writer, chosen trim cells, exact boundaries or regeneration. Current output is under `recipe_decoding`.
