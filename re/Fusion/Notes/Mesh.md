### Saved study findings

Study scripts, reports and capture paths in this section are relative to [the Study directory](../Study/README.md).

`mesh-decoding.json` adds three owned tetrahedron exports: STL imported with explicit centimetre and millimetre units, and direct triangle-data construction. Typed component mesh collections and reciprocal asset references establish the `.paramesh` member before its geometry is read. The observed UDPMESH payload contains bounded raw-LZMA buffers, Float32 vertices and a signed Int32 difference stream whose backward reconstruction yields the actual triangle indices. Native transforms preserve the small scale differences visible in API coordinates. Other buffers, normals, general mesh schemas, editing and regeneration remain unresolved.

Mesh ownership is kept precise: the two STL files explicitly reference a native Base Mesh Feature, while the triangle-data file has no such feature reference. All three API `baseOrFormFeature` getters return null despite the requested BaseFeature import/edit setup. The separate BaseFeature record remains unsupported. The original capture also retains collection-serializer errors for BaseFeature vector getters; they do not establish empty lists or ownership. Its executed source snapshot is preserved, and the reproduction generator handles vector iteration. An initially inspected SDK copy lacked Mesh Plane Cut, but all three actual runtime capability getters report it present. The executable installation also contains its API declarations. That SDK/runtime discrepancy is retained; this stage makes no Plane Cut call or successful-operation claim.

`decode_mesh_geometry_variants.py` reuses common UDPMESH framing and native ownership through explicit opt-ins, admitting only the captured six-buffer byte dimensions for 4-node/3-or-4-triangle and 6-node/8-triangle assets. Original successful tetrahedron summaries return unchanged. Position and index decompression remains strict; bounded prefixes of opaque auxiliary streams are labeled separately when a one-byte continuation probe exceeds the declared size. Literal compressed frames remain replayable, while auxiliary continuation and normal semantics remain unresolved. Open-mesh signed tetrahedral sums are explicitly not enclosed physical volumes. Stored buffer lengths provide counts; an incidental repeated header value `4` is not treated as a vertex or face count.

`mesh-normal-decoding.json` qualifies 187 stored octahedral unit vectors across eleven current meshes in ten saved archives. Exact Float32 pairs unfold into directions corroborated by saved display normals, including lower-hemisphere and millimetre-scale controls. The separate `mesh_normal_pools` summary retains serialized pool order without assigning vectors to vertices, corners or API array positions. One pool has 22 entries while the API display mesh has eighteen normals, ruling out a direct one-entry-per-display-node assumption. Original PolygonMesh normals remain unreconstructed; prior geometry dictionaries are unchanged.

`mesh-asset-header-scalar-evidence.json` compares seventeen typed asset headers with exact rational triangle sums. Sixteen closed assets agree with raw-coordinate volume; the open mesh stores zero despite a nonzero raw tetrahedral sum. Identical centimetre/millimetre source arrays retain the same stored scalar while native matrix determinants explain the different API component volumes. This supports an observed raw-volume-cache interpretation. Runtime fields remain literal because signedness, zero-volume closed cases and flag semantics are uncontrasted.

`base-feature-empty-list-decoding.json` adds partial provenance for ten mesh-study BaseFeature definitions with an absent body-pair branch and zero result-anchor list. Reciprocal controller/bookkeeping, counted native collection membership and an owned history sequence establish the graph. `base_feature_empty_lists` and feature `base_feature_empty_list_definition` expose those fields without changing the feature kind, existing direct-body diagnostic or mesh ownership. Seven reliable API empty-list observations corroborate the bounded fields; earlier getter errors and the distinction from all contained objects remain explicit. Existing paired-body controls are unchanged.

`mesh-cut-index-stream-decoding.json` recovers the previously rejected Combine Cut geometry. Its declared 576-byte index payload matches all 144 saved API indices, and all 26 component-coordinate triples agree exactly. Bounded probes exhaust the compressed input after one additional emitted zero byte; that byte, output-cap states and empty-drain state remain explicit metadata. Five genuinely truncated compressed inputs fail the complete-index comparison. The shared framing opt-in accepts only the observed ordinal/length/suffix/drain state, and the geometry callback requires the exact six-buffer Cut shape. Strict default rejection remains unchanged; no universal padding, flush or end-marker meaning is claimed. The retained tool record keeps its separate current-mesh diagnostic.

`mesh-normal-variant-decoding.json` adds five independently corroborated Remesh and Join/Intersect pools: 420 stored vectors versus 256 API display normals. Only the four observed count tuples extend the reader; all eleven earlier full dictionaries remain unchanged. `mesh-reverse-normal-decoding.json` separately corroborates the Cut pool's 93 vectors against 55 API display vectors and adds that exact tuple. Serialized pool order remains distinct from vertex/corner/API-node assignment.

`mesh-asset-error-decoding.json` corrupts only the first raw LZMA payload byte in three existing additional-asset frames, retaining their native references, UUID metadata and frame headers. The shared typed-asset reader converts the decompressor exception to `ValueError` with the original reason and cause. Reduce, Remesh and Smooth then return explicit unresolved records instead of allowing a decompressor exception to escape their summary. Valid controls/current geometry and original capture files stay unchanged.

`historical-mesh-face-group-decoding.json` recovers three previously unsupported GenerateFaceGroups features in the saved CombineFaceGroups contrasts. The feature's stored asset joins the later Combine feature's additional asset by typed native identity, and an explicit native history sequence places Generate before Combine. The selected mesh's current asset remains separate. Three Fast/20-degree settings and twenty-four stored triangle labels agree with the captured before-Combine API values. Eighty-seven checks and eight malformed guards pass; three earlier current-only summaries, three strict rejection strings and three Combine summaries remain exact. The main reader adds `historical_mesh_face_groups` and per-feature provenance, replacing only the qualified former current-asset warning. No asset50 temporal role, general lifecycle, persistent face identity or grouping algorithm is inferred.

`decode_base_mesh_feature_definitions.py` reads the observed 263-byte, empty-name singleton native BaseMeshFeature layout independently of mesh geometry. Its partial definition preserves the counted forward mesh reference, literal metadata, shared footer state and reciprocal controller, bookkeeping, feature-collection and native-history records. Twenty saved definitions replay all 5,260 payload bytes exactly; nine malformed guards pass in `base-mesh-feature-definition-decoding.json`. The forward reference alone does not qualify the mesh owner backlink, asset or current membership, so those fields remain explicitly unqualified. Feature kinds, existing diagnostics, discovery counters and timeline semantics stay unchanged.

`decode_base_mesh_sources.py` separately checks the reciprocal mesh/feature association. Current accepted routes link to the existing `mesh_contents` entry by typed IDs; their geometry is not copied. Retained routes use the stored mesh record, explicit current-collection exclusion, native asset/filename/UUID links and the same bounded geometry codec as the established selected-source reader. A neutral `decode_retained_mesh_record` factory shares that strict record grammar without inventing an operation selection. The existing `decode_retained_mesh_source` wrapper still validates its owned selection and restores its exact original scopes and dictionaries. Stored matrix composition does not establish solved historical/world placement. Parent BaseFeature, API handle assignment, visibility and lifecycle remain null.

The main reader adds only `base_mesh_feature_definitions` and `base_mesh_sources` partial summaries and per-feature `base_mesh_feature_definition`/`base_mesh_source_provenance` attachments. A retained mesh absent from the current collection is not declared currently visible, and its previously unsupported feature is not reclassified by these additions. The actual imported-mesh captures include empty public BaseFeature body getters and a null MeshBody.baseOrFormFeature; a shared native container or nearby feature index does not override that counterexample or establish a parent BaseFeature relationship.

`base-mesh-source-decoding.json` qualifies twenty provenance rows across the same sixteen files: fourteen retained records outside current counted membership and six existing accepted current routes. Nine legacy selected-source dictionaries remain exact, all sixteen prior mesh summaries or their absence remain exact, and six malformed provenance guards pass. The three low-level imported-mesh construction controls include a triangle-data case with no matching native BaseMeshFeature definition; no feature or parent relationship is fabricated for that case.

`base-mesh-definition-integration.json` compares sixteen fixed outputs against `eabb856` using one cached baseline/current pair. Fourteen files publish definition and source summaries, with twenty independently qualified attachments for each. The triangle-data and Patch controls remain wholly unchanged. After removing only the exact report-qualified new summaries/attachments, every prior complete output is identical: kinds, discovery, tool settings, timeline, retained/current mesh buffers, other partial definitions, source-selection diagnostics, ASM topology/geometry and placement labels. No unresolved row is cleared, feature reclassified or live capture added. The 707-archive corpus and existing class/naming/attribute/geometry inventories are unchanged; these partial relationships do not establish native writing, complete history replay or reliable CAD translation.
