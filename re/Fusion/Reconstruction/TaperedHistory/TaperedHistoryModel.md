# Controlled tapered circular extrusion history

## Result and qualification

A positive-radius tapered circular extrusion uses the same 35-record initial BRep inventory, nine attribute ownership roles and two-state insertion journal as the qualified circular cylinder. A taper does not introduce a distinct feature class. Its geometric cone angle, upper rim and orientation change; its editable Design taper parameter stores radians even when its expression and unit use degrees.

This report specifies the controlled saved profile and an independent implementation route. It is research evidence, not acceptance of a tapered parametric document. The separate standalone frustum writer has already passed native SMT/SMB load, measurements and save/reopen for expanding, contracting and equal-radius cases. That establishes its fresh geometric topology, not feature rebuild/history acceptance.

## Complete initial BRep grammar

The outer header is `ASM BinaryFile8` with four signed 64-bit words `23200, 0, 2, 3`, then three counted provenance strings and doubles `50, 1e-6, 1e-10`. There are two roots, the ASM header and the body. Coordinates and geometric length fields in the records are centimetres; the header value 50 is not a global coordinate multiplier.

The 35 records comprise 26 ordinary topology/geometry records and nine custom attributes:

Ordinary fields 0–2 are attribute head, stored entity identity and pattern reference. The body identity is key 0, all other ordinary identities are −1, and all pattern references are null. Integers are tag 4, doubles tag 6, strings tag 7, positions tag 19, vectors tag 20, and logical values tags 10/11.

The topology is a three-face closed shell: the conical side has two one-coedge loops; each cap has one one-coedge loop. There are no wire bodies, open trims, subshells, pcurves, transformations, tolerant entities or nested geometry subtypes in the control. Both boundary edges are closed circles spanning −π through +π, with identical start/end vertices. Upper and lower vertex owner indices are 2 and 0 respectively; these must be retained for source reconstruction.

## Cone parameterization and taper sign

For this +Z, forward-sense circular profile:

```text
theta_rad = theta_deg * pi / 180
topRadius = bottomRadius + height * tan(theta_rad)

sinAngle = sin(theta_rad)
cosAngle = cos(theta_rad)
parameterScale = bottomRadius
radius(z) = bottomRadius + z * sinAngle / cosAngle
```

Equivalently, fresh geometric input in terms of two radii gives sine `(rt-rb)/hypot(h,rt-rb)` and cosine `h/hypot(h,rt-rb)`. Those algebraically equivalent calculations need not produce bit-identical floats to a native angle evaluation. A reader should retain the actual typed trigonometric fields and geometric carriers, validating their agreement within the declared numeric contract.

The independent semantic range should initially require `−90 < theta_deg < 90`, positive finite height and both positive radii, with representable geometry. Reject an apex, a radius crossing zero, a zero representable cosine, overflow, or a sign/direction mismatch. Zero angle is the cylinder limit, not an error. Negative angles contract along +Z, but the negative-angle corpus example is a subsequent Draft feature; it does not by itself establish negative tapered-extrusion history support. Native acceptance of a freshly authored contracting extrusion remains required.

[FrustumModel/ConeEvidence.json](../FrustumModel/ConeEvidence.json) holds the decoded taper records and their ground truth. The sine, cosine and length-scale sequence and the parameter roles rest on those records and on the accepted native frustums in the [frustum model](../FrustumModel/FrustumModel.md). No additional native calls were made for this report.

## Derived geometric properties

For base radius `a`, top radius `b`, height `h` in centimetres, let `d=b-a` and use the base-centered axial coordinate `z`. Analytic geometry gives:

```text
V = pi*h*(a*a + a*b + b*b)/3
A = pi*(a*a+b*b) + pi*(a+b)*hypot(h,b-a)
zbar = h*(a*a+2*a*b+3*b*b)/(4*(a*a+a*b+b*b))
J4 = h*(a**4 + a**3*b + a*a*b*b + a*b**3 + b**4)/5
Z2 = h**3*(a*a/3 + a*d/2 + d*d/5)
Izz_base = pi*J4/2
Ixx_base = Iyy_base = pi*J4/4 + pi*Z2
```

These inertia integrals are about axes through the base center with density one; a translated body requires translation of second moments and product moments, and any native cache contract must use its established reference frame. The control's stored geometric cache has volume 6.533057919954656 cm³, area 19.61636501856793 cm², center Z 0.9033932075833666 cm, and approximate moment vector `(8.911809723623081,8.91181045979142,4.043132092296158)`. Numerical integration precision and provenance fields should not be invented from those particular captured values.

## Promotion plan

1. Add an explicit circular-history geometric classifier after bounded wire framing. Inspect the qualified side surface type/fields, cap/rim topology and radius law. Zero-angle/equal-radius profiles identify cylinders; finite nonzero signed angle with two positive radii identifies the qualified frustum. Unsupported axes, ratios, ranges, offsets or contradictory topology must reject explicitly. Do not attempt one parser and reinterpret its arbitrary exception as another format.
2. Reuse the common topology allocator, attribute grammar and journal serializer. Construct the frustum's 26 plain records from semantic inputs, append the same nine independently generated attributes and assign heads by the existing semantic roles. Set body identity and journal IDs from the Design contract. No raw history or source block is an authoring input.
3. Introduce a typed circular carrier/orientation representation for source reading: cone center/axis/major vector/ratio/sine/cosine/scale/sense; both rim centers/normals/major vectors/ratios and intervals; cap frames; edge intervals and sense; coedge senses; seam-point coordinates; vertex owner endpoint indices. Preserve actual numeric fields and validate them against the selected semantic shape. Retain only the fields admitted by the explicit profile; reject extra records/attributes/archives rather than carrying opaque tails.
4. Expose a signed angular parameter on the document specification. Generate the same Design feature graph and fresh IDs, encode degree expression with radian value in both parameter and binding, and derive the top radius from the driving length and angle. Update the body property cache through an analytic frustum model or an independently proven lazy-cache policy. Keep material references and all existing identity joins intact.
5. Add remote compatibility coverage using the +7-degree control and +5-degree holdout; preserve source top-carrier orientation and native endpoint indices on read/reemit. Include direct qualification rejection for the negative Draft archive's additional journal states. Add independently authored expanding/contracting documents and invalid apex/cosine/radius cases at the real document boundary.
6. Native acceptance must inspect correct geometry before `computeAll`, roll back to sketch-only and restore, recompute, edit taper and driving length independently, verify the expected upper radius/volume/center, save and reopen, then verify editable healthy features again. A separate source read/reemit native roundtrip must exercise the retained −Z upper carrier. These checks are pending for tapered parametric documents.
