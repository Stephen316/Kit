## Root and asset manifest wire recipes

All integers are little endian. `s` is `u32 byte_count` followed by narrow string bytes; observed strings are ASCII. `w` is `u32 UTF16_code_unit_count` followed by UTF-16LE. Preserve the distinction, particularly for titles and Unicode names.

Root order:

1. `s("3-2-0-0")`, `s("FusionDocType")`, `w(".f3d")`, `w(title)`, `w(description)`, two `w(document_guid)` fields
2. `u32(1234)`, `u32(20)`, `u32(17)`, `u32(709361728)`
3. `u32(7)` followed by `(s key, u32 version)` entries: Application 1, CAM 4, ParaMesh 8, SimCommon 30005, SimFEACSObjects 2, SimFluidDynamics 2, SimStructuralAttributes 10002
4. `u32(0)`, `u8(0)`, `w(active_asset_guid)`, `u32(1)`, `w("FusionAssetName")`, `u32(0)`, `u8(1)`, `w("NA_EXPORT")`

Asset order:

1. `w("FusionAssetName")`, `w(asset_guid)`, `w(snapshot_guid)`, `s("FusionAssetType")`, `u32(20)`
2. `u32(4)` and version entries Application 139, ParaMesh 13, Server 36, VolField 4
3. `s("Neutron3DAssetType")`, `u32(0)`, `u8(0)`, `u32(property_count)`
4. Zero properties for the empty control; one `(s("physicalChangeGuid"), w(guid))` for the extrude
5. `u32(0)`, `u32(5)`, `u32(3)`; three rows `(u32 segment_id, s kind, s kind)` for IDs 0 Design, 1 ACT, 2 Browser

The word 5 is recorded without assigning unsupported semantics. The current production `ReadAssetWire` and `EmitAssetWire` require exactly one physical-change property; this excludes the observed valid zero-property empty manifest. A generalized typed property vector is required. Fresh UUID generation is mechanically possible, but the first two document UUIDs' precise lifecycle meanings remain unproven.

## Segment framing and write order

ACT and Browser use the same metadata and bulk mechanism as Design. Their metadata headers carry their kind, segment ID 1 or 2, zero namespace UUID, magic 1234, wire version 8, words 17 and 709361728, repeated kind, storage name `Fusion`, storage discriminator 5 or 6, and zero word.

The class table supplies class UUID, base UUID, persisted schema version, namespace and owner IDs. Codes start at 256 in table order. Then follow additional IDs, primary `(u64 entity_id, u64 bulk_offset)` entries, continuation entries of the same shape, an allocation-watermark-sized `u64`, a zero `u32`, and version properties. ACT has Application/Server 1; Browser has 2. The observed tail is 8 for empty ACT, 11 for extrude ACT, and 33 for Browser. Extrude ACT has ten live entities but watermark 11, so this field must not be replaced with a record count.

Each bulk record starts with the decimal class code encoded as `s`, then `u64 entity_id`. Its payload starts with a root-ID string. Primary payloads additionally carry subject and named-metadata flags/lists. Continuations carry only the root string before class data. Payload lengths come from the sorted index boundaries. Serialize each class's persistent own member set in its evidenced order, then its inherited sets, stopping where a separately indexed continuation begins. Use the exact persisted schema version rather than the native current version.

References in these controls are `u8 present`; if present, `u64 entity_id`, `u8 cross_asset`, `u8 cross_segment`, and optional `u32 segment_id`. Cross-asset references are absent here and unsupported by this reader. Local references are 11 bytes including the present byte; cross-segment references are 15. The frame's observer slot is a signed `i32` following each reference. Lists/maps carry `u32` counts. Keep unordered-map entry order as data for byte-preserving reading; do not infer that the control's incidental order is required for authoring.

## Browser semantic construction

The Browser has 33 primary entities plus a ManagedEntity continuation for ID 0. Its root is `PersistBrowserRootId`, ComponentInstance is Design `(0,57)`, `autoExpandRootNode` is true and rootEntry is local 1. Its typed passive lookup map associates Design entities with Browser entries; its string lookup map disambiguates entries sharing a Design owner. The continuation gives the root a null parent.

Entry 1 links ACT `(1,6)` and Design component/instance subject references. Its children are 2–11 and 16–28. Entry 2 DocumentSettings owns 29–32. Entry 11 Relationships owns 12–15. Every ordinary child has local root 0 and reciprocal parent references. The other empty folders include named views/lights, selections, contacts, origin geometry, visual analyses, motion studies, joints, bodies, canvases, annotations, decals, sketches, construction, edit-in-place contexts, surfaces, custom groups, SubD and arrangements. Full class UUIDs and field values are in the report rather than duplicated as an opaque fixture.

Do not generate only the root lookup record: all entry nodes, observer frames and parent/child references are needed to represent the observed state. Observer `indexInObserverVec` must agree with the referenced Design subject's observer collection. Entry 1 has four subjects; PMISettings has two; most others have one. DocumentStructureType has a null base `entity` but observes Design `(0,6)` and uses a string lookup key. IDs shown here are the controls' choices, not globally fixed IDs; any reallocation must update all fields and indexes together.

## Protein material package

The protein blob is an ordinary nested ZIP with a package UUID directory, XML connection/core documents, content types, `AssetData/StreamVersionTable`, three binary data files and schema XML. The version table declares table-of-contents 3.1, definition iterator properties 3.2, instance properties 3.2 and asset-library version 1.0. XML trees, attributes, text and relationships are represented in the report. Recreate XML from a typed package model; preserving source XML bytes is not an independent serializer.

`AssetTableOfContents.bin` is a sequence without a leading count. Each row is `s(instance_id), s(role), u32(definition_root_block), u32(instance_root_block), s(schema_name)`. Empty has four rows; extrude has six. Roots address the corresponding property files' block indexes, not byte offsets.

Both property files have a 16-byte header: `u32(136), u32(0xffffffff), u32(0xffffffff), u32(0)` in these fresh controls. Each 136-byte block has `u32 next_index`, `u16 used_length`, `u16 flags`, then 128 bytes of storage. Flag 1 marks a chain's first block; continuation flags are zero. A next index of `0xffffffff` ends the chain. Concatenate only the used payload. Reject out-of-range links, cycles, shared chains, impossible lengths and unexpected unattached blocks. The layout is observed in the controlled saved stores. An independent writer can allocate consecutive blocks, emit these headers and zero unused storage.

Definition records consist entirely of sorted properties whose schema declares `definitionIteratorData=true`: `s(BaseSchema)`, `u8(Hidden)`, `s(UIName)`, `s(VersionGUID)`, counted string `category`, `s(description)`, counted string `keyword`, counted string `thumbnail`. They have no separate fixed schema/definition-ID header. The `VersionGUID` field's declared `Uuid` type is serialized as a string; its observed values such as `PrismMaterial-018` are not UUID-shaped and must not be coerced to binary UUIDs. Every definition record in both controls ends exactly after these fields. Instance records begin with three strings: schema, instance ID and definition ID. The following string belongs to the first sorted instance property, `AssetLibID`; it is not a fourth fixed header field or a version GUID. Remaining instance values require the schema's property ordering, type encodings and connection records. Their bodies total 1298 bytes in empty and 1871 bytes in extrude. These bytes are not solved by exposing them as an opaque payload. Further decoding is tracked in the separate `ProteinInstances` research directory.

The used-length boundary matters: native exports contain unrelated text in unused storage. Arbitrary string scans of the full allocation produce false semantic evidence and may reproduce incidental memory fragments. Reports omit unused storage contents; a writer should zero padding. The two empty streams contain 592 unused bytes; extrude contains 905.

Cross-check TOC IDs against instance headers, TOC roots against first-block flags, schema names against available XML schemas, schema Base dependencies against the schema set, and material references inside Design against the emitted instance IDs. The `.protein` filename must match the Design blob trigger. Material omission is not established: even the empty document references physical and appearance material assets.

## OGS and smallest empty candidate

The world prefix decodes as `w("ARenderList"), u32(5), u32(1), w("GroupNode"), w(runtime_like_handle), u32(9)`. The remainder is a typed scene/attribute registry. `stream_mesh_000` is packed binary geometry; the prefix contains float vertex data and index data, but the complete world/buffer association remains unresolved. Pointer-shaped labels must not be interpreted as stable document IDs.

Earlier binary inspection suggested why Fusion tolerates missing OGS members. That explanation is not part of the black-box evidence.

The parent subsequently established native acceptance for the controlled cylinder: [NoGraphicsRewrite.json](../../LocalOracle/Features/NoGraphicsRewrite.json) removes all five OGS entries from the typed 19 mm document, producing SHA-256 `23b01576ce5eaf635eeabb76bcce520d5c57777bfdd00e7dec496578e9c66bfa`. [NoGraphicsAcceptance.json](../../LocalOracle/Features/NoGraphicsAcceptance.json) records correct initial 19 mm height and 5.969026041820864 cm³ volume before native recomputation, preserved sketch/extrude timeline and linked parameter expressions, successful recomputation, an edit to 23 mm, and save/reopen preserving 23 mm and 7.225663103256217 cm³. Status is `accepted`, Fusion is 2706.1.17, and documents remaining is zero. This establishes omission for that same-source typed Design plus independently generated cylinder BRep and journal. It does not establish arbitrary cache-family omission, source-free envelope construction or a visual comparison.

The smallest evidence-backed candidate plan is root manifest, zero-length Properties, zero-property asset manifest, independently authored Design, independently constructed ACT and full Browser, and the two empty config JSON files linked to their triggers. Protein needs complete typed instance serialization or a separately established semantic default-material route. Previews may be generated independently. OGS may be omitted for the accepted controlled cylinder profile; omission from a newly authored empty graph and omission of previews still need acceptance.

A source-free acceptance candidate must obtain fields from an authored document model, class/schema metadata and structural relationships. Loading `EnvelopeMaterial.json` and replaying every captured value would still be a donor fixture. The JSON exists to describe grammar and constraints. No existing metadata/bulk blob, source archive, captured material property tail, mesh cache or byte patch is an acceptable substitute for the missing model.

## Remaining constraints

1. Use the completed controlled material serializer and native acceptance evidence; qualify additional material schemas before extending support.
2. Extend the bounded OGS omission acceptance to an independently authored empty graph and independently generated previews, then check display and geometry.
3. Derive the empty Design graph and shared observer ordering from semantic constructors, with consistent ACT and Browser references.
4. Rebuild metadata class owner sets, offsets and allocation watermark from the generated graph; preserve legitimate gaps.
5. Validate the zero-property asset-manifest variant and independently generated IDs through native load/save/reopen.

No production readiness, full lossless material conversion, arbitrary assembly support or source-free F3D acceptance is claimed by this research.
