The archive replay used only the eight generation-19000 P03 saves from capture revision `466dcb172dfa3803463e07ccde963ba01671d200`. It verified the sealed receipt, measurement receipt, and native file sizes and hashes before decoding each appearance. At VisualStates byte 460, the RealView ID is 3 in every save. ## Native allocation paths

Addresses are RVAs in the pinned installed SOLIDWORKS 34.4.1.1011 modules. The document manager constructor sets its counter to 1 at `sldmodu:0x10aee0e`. The exported allocator at `0x10bd340` returns the current 64-bit value then increments it. The model wrapper holds the document manager at `+0x18`. `moModel_c::createPWMaterialManager` receives the document manager, constructs the wrapper and attaches it at `0xed86e6–0xed86f9`. On the standalone holder path, `sldvisualstateu:0x96689–0x966f2` obtains the wrapper or creates it from the document's manager. [Native module SHA-256 pins](VisualStateOwners.md#evidence-pins)

- **Cold default appearance.** `sldmodu!getDefaultAppearance` checks the process-global initialization flag at `0x10bb8ee`. If it is clear, `0x10bb8fa` calls the initializer at `0x10b93c0` with the supplied model. The initializer passes that model and the process-global property to `setVizPropsFromFile` at `0x10b961e` and sets the flag at `0x10b967a`. The `.p2m` dispatcher at `0x3ac3a5–0x3ac3c4` reaches the file-material branch at `0x3a9100`. On the successful branch with a model, wrapper and document manager, `0x3aa7d6` obtains one ID and `0x3aa7e6` installs that RealView property. This allocation belongs to the property prepared for the process-global default.
- **Copy into a model property.** The caller copies the global property at `0x10bb909`. If the copied material has no RealView child, the fallback builds a path ending in `materials\color.p2m` and calls the same file-material helper at `0x10bb9a5`. When a model and its attached manager are available, `0x10bba09–0x10bba1e` separately obtains the current counter, increments it and writes the obtained value into the destination's RealView ID. The cold branch with successful global initialization and a copied RealView can consume two consecutive IDs in one call. A warm branch with a populated global property skips initialization and consumes one.
- **Apply the model default.** The exported `setDefaultAppearanceOnPart` at `0x10c4b30` checks a model virtual predicate and enters for an absent visual property or one with the default-appearance word `+0x5c` set to 1. It builds the new value at `0x10c4b99`, installs or assigns it on the model at `0x10c4be8` or `0x10c4c1e`, and applies the same value to its configuration at `0x10c4c3f` or `0x10c4c82`. It then notifies the visual layer with the self-component holder. This is a concrete allocator-to-configuration path. The saved CMgr transition alone cannot identify the particular native call that produced it.
- **Prepare the holder.** `sldvisualstateu:0x9670a` skips conversion if the selected material already has a RealView child. Otherwise `0x96724` calls `sldmodu!CreateAppearanceVizPropFromVizProp`. The default-conversion branch at `0x10b2c9a–0x10b2cb5` assigns an ID only when the new RealView's ID is zero and the wrapper is present. With a document manager attached, it increments that manager's counter and stores the previous value in the RealView. The holder attribute copy at `sldvisualstateu:0x4a0e9` reaches the material's RealView copy constructor through `sldmfcu:0x201195`, `0x200948` and `0x12ee25`. The copy preserves the full existing ID at `0x12e595–0x12e598`. [Holder construction](VisualStateOwners.md#component-and-attribute-references)

The original assignments for IDs 1 and 2 and the holder's saved ID 3 remain unresolved. Fresh P03 authoring calls `INewDocument2` with an installed part template, and its first stage measures a healthy control before building baseline A. Neither action yields a sealed counter or process-global initialization state at the start of authoring. A counter and destination trace across the existing fresh authoring and reopen sequences would distinguish a cold default preparation from warm creation, template restore and a later holder assignment. ## Installed template state and native restoration

The capture harness uses `GetDocumentTemplate(1, "", 0, 0, 0)` and passes its result to `INewDocument2`. The sealed P03 receipt and measurement record identify the recipe, executable build, process boundary and eight saves. They omit the resolved template's identity and the preauthoring material state. A separate read of the currently installed `Part.PRTDOT`, 20,661 bytes with SHA-256 `e338c3a1de8734934e78c3fa1558833330ee54cec13fc38f9d8f0f460e97954a`, establishes an independent template with generation 19000. Its relationship to the historical template remains unknown. In `sldapiu` the API imports `auAm_c::iNewDocument` from `sldappu`. The native routine at `sldappu:0x4bd120` tests the supplied filename and opens it through `CAmApp::OnLocalFileOpen` at `0x4bd424` before applying new-document settings. `uiModelDoc_c::Serialize` separately establishes the guarded restore contract. At archive version at least `0xf1e`, `slduiu:0x862ed8` reads a manager-presence byte and the nonzero branch calls the manager at document member `+0x1110` at `0x862eef`. The latter restores the two words forming the counter. The VisualStates reader at `sldvisualstateu:0x7c9b0` reads the saved graph at `0x7cda9` before its conditional representation builds at `0x7d2e3` and `0x7d3a1`. These guarded native routes make inheritance of holder ID 3 with next ID 4 possible. The template-specific execution order across those routes remains unobserved. A licensed observation can pin the exact template selected by the API before calling `INewDocument2` and retain its digest after close. Scope the trace to the existing-file branch from `sldappu:0x4bd424` to its return at `0x4bd429`. Record the document manager identity and counter at the restore call and return (`slduiu:0x862eef`, `0x862ef5`), and the saved holder's RealView ID after graph extraction (`sldvisualstateu:0x7cda9`, `0x7cdae`). If the fresh holder route runs, record the owning model and assigned or copied ID at `0x932d0` and `0x4a0e9` for that same document. Preserve template and output hashes and identify which object received each ID. This distinguishes a restored holder from an allocated one even if both ultimately save ID 3.
