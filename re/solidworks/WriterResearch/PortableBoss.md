# A12 portable rectangular boss mapping

This research maps the P03 discovery profile from [`CadDocument`](../../../src/interchange/document/Models/DocumentModel.py) to candidate SOLIDWORKS records. Source inspection used PR #94 revision `08f2f8e6514ca1dfcf8a2dba98845d1c53430af1`. The [step register](../../../Documentation/Reference/Research/AutomationSteps.md) tracks A12 and its dependencies. This map has archive and historical native-control evidence. Independent synthesis and native acceptance are pending. `vendor_loadable` and `application_usable` remain unverified.

## Discovery evidence

[P01 and P03](../../automation/PairSpecs.json) specify an origin-anchored 40 × 20 mm rectangle on XY and a forward 10 mm blind additive extrusion. The [SOLIDWORKS capture receipt](../../automation/PairedCaptures/P03/solidworks-db1390476325/receipt.json) pins `P03-solidworks-baseline-a.SLDPRT` to SHA-256 `db1390476325f5817e6f80fb4067a3c6df5cc063315604c133ccbeaafdeac357`. The [measurement receipt](../../automation/PairedCaptures/P03/solidworks-db1390476325/measurements.json) records SOLIDWORKS 2026 `34.4.1`, one body and a center of mass of `(20, 10, 5)` mm. The corresponding [Fusion receipt](../../automation/PairedCaptures/P03/fusion-8d53584027ff/receipt.json) pins its independently authored baseline to `9f109b98ab7d36abeda8d9f88f9b336277238ce0bb3336d99313253ad47b2745`.

The [paired archive report](../../../Documentation/Changes/Research/Readers/Comparison/RectangularPairEvidence.md) compares eight P03 signed displacements and selected profiles. Fusion records `create` and SOLIDWORKS records `join`. Their height dimensions select the same side with opposite operand order. The SOLIDWORKS corner rectangle uses shared sketch points and the reader reports four inferred endpoint coincidences. The report preserves these distinctions. Discovery captures may exercise the inverse and constrain the format grammar. Use separate provenance for independent qualification and leave the reserved P05 holdout unopened for this work.

## Portable mapping

The first candidate targets generation `19000`, one standalone placed-on-Front-plane sketch and one forward blind boss in one active metric configuration. Treat each row as a requirement for the candidate. A successful parse establishes the saved field and identity joins. Construction additionally needs a target allocation rule and a justified value for every serialized field.

## Refusal cases

The [registry write boundary](../../../src/convert/adapters/registry/RegistryWriteApi.py) owns common checks and transactional destination handling once a writer has been selected. The [SOLIDWORKS adapter](../../../src/convert/adapters/solidworks/Core/Adapter.py) currently provides read operations. The target-specific rows below define required refusals for a future P03 writer. Apply the scoped check before candidate generation and preserve existing files and streams when it refuses an input.

| Candidate input                                                                                                                                                         | Required refusal                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Unqualified research JSON, unframed or fallback support, unresolved native dimensions or equations                                                                      | Preserve the existing evidence and refusal. Relabeling the source or serializing to interchange JSON cannot qualify the underlying declarations. ## First generative check

The [resolved boss opening](BossOpening.md) constructs the named feature and primary transfer fields from the live profile, trim file and configuration atom. It reaches the chooser boundary in the eight P03 discovery saves.

The smallest geometry-bearing candidate is the typed blind-end/depth record for one already validated symbolic sketch-and-boss graph. Allocate its class and object references from symbolic owners. Derive the positive length scalar and both copies from the requested parameter. Decode the generated record with the existing [blind-end and depth readers](../../../src/convert/adapters/solidworks/Resolved/BossEnd.py) and confirm that changing only the requested depth changes that owner's length and derived copies. A saved record helps verify the reader and field map. Its offsets, row values and byte ranges supply no candidate input.

The whole-file experiment still needs constructed configuration and resolved archives sharing the actual allocated namespace, plus the model header and required streams. The retained [archive tags](../../../src/convert/adapters/solidworks/Container/Archive.py), [definition](../../../src/convert/adapters/solidworks/Container/Definition.py), [configuration manager](../../../src/convert/adapters/solidworks/Container/Cmgr.py) and [container codec](../../../src/convert/adapters/solidworks/Container/Container.py) are reusable. The container call takes generated streams using its supported default file ID, with no template. An emitted record or packaged archive alone does not establish native loadability.
